## 如何解释 GRPO 对照

从预训练 Base 到 GRPO-25，原 benchmark 的成功次数在 Dev、IID、OOD 上分别变化 +0、+24、+3 次。这个差值包含 Native SFT v2 和后续 GRPO 两个阶段。若要隔离追加 25 步 GRPO 的效果，应比较 Native SFT v2 和 GRPO-25。两者在原 benchmark 分别为 83/93 和 78/93。新留出题数较少，单个试次的增减对结论影响较大。

## 历史记录、复现与产物

此前的 v4_86 归档保留了预训练 Base 的 46/93（Dev 17/24、IID 20/57、OOD 9/12）。该运行的有效生产提示词、工具 schema、根种子和关闭 thinking 的设置与本轮相同，提示词所在的源码文件整体有过改动。官方后训练版也有 v7_86 的历史记录，切分版本不同。新 E2-Repair Benchmark 的既有模型清单只有 SFT v2、GRPO-25 和三个 DAPO 检查点，本次补齐了两个原始模型。

新 Dev 的种子从 73000 开始，新留出从 85000 开始，生产集根种子为 42。新留出在前序实验已启封，此次为固定协议下追加的基线比较。五个既有策略共 300 条新 Benchmark 轨迹经 CPU 回放复核，与原评分逐条一致。可评分的分母随模型执行路径变化。

评测冻结 SHA-256 为 `9463c4d16daa4787571341b8f15b851b935c51cec6746747f94dedcd1e2bc0d2`。两款模型分别保存 153 条原始轨迹，GPU 整卡采样峰值为 20,494 MiB。
