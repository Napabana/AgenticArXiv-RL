# Qwen3.5-2B 原生 Tool Calling 边界修复后复测

2026-11-21，修复后的原生 Tool Calling 在 31 个留出任务上各运行三次，严格成功 **72/93（77.4%）**，比修复前多 12 次（+12.9 个百分点）。四道题由三遍均失败变为三遍均通过，其余 27 道题的成功次数持平。273 个模型响应全部通过格式解析，逐轮扫描未发现完整调用之后由模型续写的 `<tool_response>`。 [本次汇总 JSON](qwen35_native_tool_calling_fixed_benchmark_20261121.json) · [修复前评测](qwen35_native_tool_calling_benchmark_20261121.md)

## 评测设置

运行使用修复提交 `fae3fcfb0482ccc51332d911127adac6fa5db386` 中的四个推理与评测源文件。单张 RTX 4090 通过 Transformers 5.16.1 直接以 BF16 加载 `Qwen/Qwen3.5-2B`。这里的 Base 指项目未加载 SFT 或 GRPO Adapter 的官方后训练模型。温度为 0.1，关闭 thinking，基础随机种子为 42，每个任务和试次独立派生种子。离线工具使用同一份 `MockArxivEnv` 快照，沿用 `v7_86` 切分和原严格评分器。三个切分 GPU 运行合计 23 分 25 秒。 [任务切分](../data/splits/v7_86.json) · [修复提交](https://github.com/Napabana/AgenticArXiv-RL/commit/fae3fcfb0482ccc51332d911127adac6fa5db386)

修复前经本地 API 桥接 Transformers，三次运行各从请求序列种子 42、1042 和 2042 开始。本次整体差值是跨运行观察值。此前对同一模型、同一提示和同一种子的五个首轮样例做了定向验证，其中四个在旧协议下因尾部续写丢失完整工具调用，修复后这四个调用均执行，真实结果以带调用 ID 的 `role=tool` 消息回填。

## 协议、执行与开销

| 指标 | 修复前 | 修复后 |
| --- | ---: | ---: |
| 格式解析成功 | 211/232（90.9%） | 273/273（100%） |
| Schema 合规 | 139/142（97.9%） | 184/187（98.4%） |
| 工具序列准确 | 66/93（71.0%） | 78/93（83.9%） |
| 平均参数准确度 | 72.8% | 81.5% |
| 实际工具执行错误 | 3/139（2.2%） | 10/184（5.4%） |
| 平均执行调用数／任务 | 1.49 | 1.98 |
| 平均总 Token／任务 | 7,366 | 8,749 |
| 平均 LLM 耗时／任务 | 9.43 秒 | 14.57 秒 |
| 完整调用后续写工具结果 | 12 轮 | 0 轮 |

格式解析按模型响应计数，Schema 合规按可解析的工具调用计数，执行错误按实际执行的调用计数。参数准确度是逐任务参数得分的平均值，包含部分得分。修复后 180 次执行过的调用后面还有下一轮模型决策，印证多轮路径得到覆盖。10 次工具执行错误集中于两项难以完成的任务，Dev 的邮件任务产生 6 次，IID 的越界下载产生 4 次。

修复前有 21 次格式失败，其中续写工具结果 12 次、生成到达长度上限 6 次、同轮多调用 3 次。12 次续写中有 8 次的首个工具和参数符合当步预期。修复后的轨迹覆盖了更多模型响应和真实工具调用，实测 Token 和耗时同时上升。完整评测和定向复测共同支持保留生成边界修复。原生接口与 ReAct 的独立收益仍需要同一推理接入和取样条件的对照。

## 剩余失败

以下七道题三遍均未达到严格成功。Dev 和 IID 的模型响应均通过格式解析。

| 切分 | 任务 | 轨迹与判分原因 |
| --- | --- | --- |
| Dev | `constraint_search_no_file` | 漏传显式 `aspect="*"`。默认值仍会搜索所有分类，参数得分为 0.75。 |
| Dev | `infeasible_unsupported_action` | 用户要求发送邮件。评分要求说明无法发送且零调用，模型却反复搜索和读取论文，最终达到轮数上限。 |
| Dev | `state_dl_then_cache` | setup 已经填好论文列表。模型先重复检索，然后下载并检查缓存，多余的检索使工具序列失分。 |
| IID | `chain_cl5_dl3_tr3` | 首步工具选对，`aspect="cs.CL"` 不在工具枚举中，Schema 要求 `"CL"`。三遍均在执行前终止。 |
| IID | `constraint_translate_only` | 只调用了翻译工具。标准参数是 `ref=null, keep_dual=true`，模型传了 `ref=1` 且漏了 `keep_dual=true`。Mock 接受了提交，真实工具默认只保留单语产物。 |
| IID | `infeasible_index_out_of_range` | 会话仅有 5 篇，模型仍调用 `ref=20`，随后扩大搜索范围并重试。两遍下载了新列表里的第 20 篇，一遍耗尽轮数。评分要求根据原列表说明越界且零调用。 |
| IID | `ref_stress_learning_state` | setup 已经给出可用列表，预期直接按标题片段调用 `download_arxiv_pdf(ref="Learning State")`。模型三遍都先重新搜索，再用位置或完整标题下载。虽然找到了目标论文，额外的搜索仍违反严格工具序列。 |

本次重跑范围是修复后的原生组。评测没有新增在线 arXiv、真实下载或真实翻译验证。
