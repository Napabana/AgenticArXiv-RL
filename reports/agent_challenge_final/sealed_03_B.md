# 封存题 03_B：顺序是否造成误判

> 甲、乙分别指开始时的候选列表的第1篇和第4篇。先查甲的缓存，已有文件时读摘要段；随后查乙的缓存，缺失才下载；最后为乙作120字结构化摘要。

在模型接手前，环境已经生成候选列表并缓存甲。专家第一次查甲时返回 `pdf_ready=true`，第一次查乙时返回 `pdf_ready=false`。甲为 `2611.18563v1`，乙为 `2611.18559v1`。两次独立专家回放均按以下顺序完成：

1. 查甲缓存（第 1 篇）。
2. 读甲的 abstract。
3. 查乙缓存（第 4 篇）。
4. 下载缺失的乙。
5. 为乙生成结构化摘要，`style=structured, max_words=120`。
6. FINISH。

## 放宽顺序的反事实检查

允许任意顺序、额外调用与额外读取，忽略最终终止状态，只要求五项必要操作至少成功出现过一次；按实际 Observation 的 paper_id 核对甲、乙，对读取核对 section，对摘要核对 style 和 max_words。严格评分 0/9，通过这个宽松口径的同样是 0/9。7 次为乙做好了摘要却漏读甲的摘要段，另外 2 次读到了甲的摘要段，却没有下载乙、为乙作摘要。

本例的固定顺序有“先、随后、最后”的明确文字依据。严格成功率同时掩盖了 7 条轨迹已完成 4/5 个子目标的事实。将部分完成程度单列，有助于定位问题。其他任务是否把独立操作错误地固定为唯一顺序，须分别核对用户文字和可交换步骤。
## 指令自然度

原指令用“甲、乙”绑定列表序号，并将缓存检查、分支、执行次序和输出格式写在同一句话中。“读甲的摘要段”要求取已有文本，“为乙作摘要”要求生成新内容。这种按工具流程编排的表达适合显式约束压力测试。自然用户只要求“给我第一篇的原文摘要，再把第四篇总结在 120 字以内，缺的 PDF 帮我下载”时，缓存检查的实现方式可以交由 Agent 决定。本次没有对自然表达做配对评测，无法由这里的 0/9 估计普通论文请求的成功率。
