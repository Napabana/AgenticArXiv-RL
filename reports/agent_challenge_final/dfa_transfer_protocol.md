# E2 单方法实验

用户在首轮采样过程中选择先验证 DFA。原四方法实验继续按预注册的十项条件报告。单方法实验的结论限定于经筛选的 DFA 局部对照任务，无法用它估计 E2 相对 E1 或 E4 的收益。

## 训练数据

- 只看 Train 的 Frozen Probe。每题采完八个 G=4 组才参加筛查。含环境异常的整组保留在原始数据中，从单方法的筛查分母排除。
- 同一题至少两组在相同 DFA 状态出现不同动作、可核验的正确步骤和首错、非零原始 DFA 优势。可评分组内的截断轨迹比例至多 25%。
- 单独冻结 Smoke 和 Pilot 的输入文件，记录当时已完成的题、每组 SHA、保留组编号、对照组编号和固定训练计划。Dev 结果不参与选题。
- 四步 Smoke 从最早冻结的可用任务列表中取四道不同任务。25 步 Pilot 从同一 SFT v2 起点重新加载，单题最多出现三次，至少 13 组来自四次以上调用的长任务。达到固定计划容量后冻结 Pilot；持续的 Probe 仍记录其余任务。
- 每一步重新从训练时的模型采 G=4。局部优势使用既有 E2 配方，首错保护沿用 Credit v2。终局、局部各占 0.5。组内奖励无方差时仍可使用真实可验证的 DFA 对照。在线 rollout 出现环境无效成员时，整组的策略和 KL 更新 Token 均掩码为零；调度器仍消耗该组的固定步数。所有原始分数与轨迹留存。
- 学习率 5e-6、KL 0.04、TRL 1.17.1、dapo 归一化、BF16 和原 SFT v2 提示词保持冻结。每个训练产物记录非零总优势 Token、非零 DFA Token 和排除组。五维 Reward 仅作为诊断。

## GPU 与评测

一条冻结采样进程和一条独立训练或评测进程共享 RTX 4090。另一半尚未采完的 Probe 在前半结束后续采原 Seed。Dev 基线使用最新 SFT v2 在 Challenge 的 8 个任务上各采 3 次。E2 使用同一评测入口、任务与 Seed。Sealed Test 只在 Dev 配置冻结后执行。原生产集的 83/93 为独立回归基线。

四步模型的 Dev 诊断结束后，若 25-group 固定计划的入选题仍不足，空出的执行位置可回填原来暂停的采样。回填进程持有运行目录的 `idle-slot.lock`，并使用 `probe.py --partition back --yield-when RUN_DIR/pilot_inputs.json`；正式计划冻结后在一个完整组落盘时退出。E2 在锁释放后加载模型，采样期间每个分片仅有一个写入者。

单方法训练入口为 `scripts/agent_challenge_final/dfa_transfer.py`，接收 `--probe --output --base --adapter --snapshot`。加 `--smoke` 执行四步，加 `--freeze-only` 只冻结数据。配对工具使用 `paired.py RUN_DIR dev --dfa-only` 或对应的 sealed_test 命令。

CPU 验证覆盖无效组整组掩码、原始标签保留、冻结后的 Smoke 输入不可变，以及既有 Native Agent 回归。完整套件 1093 项通过、6 项跳过、704 个子测试通过，11 条已有警告，耗时 180.05 秒。

## 正式步数修订

初始 Pilot 计划 25 步。23 道候选完成筛查后有 8 道入选；最后一道 08_B 已经超过全题允许的截断量，无法成为第 9 道。用户选择正式跑 **24 步，每题恰好 3 次**，保留全部筛选标准。24 个组中 12 个来自至少四次工具调用的任务。2026-11-25 21:39 启动，Pilot 从原始 SFT v2 初始化。最后一个候选的余下 Probe 按原 Seed 收齐。原四种方法共同消融的 25 步预算不变，本次单独实验使用 24 步。
## 等预算的全题覆盖对照

2026-11-25 22:02，按用户决定启动第二个独立 E2 Adapter。筛选组使用 8 道训练题各 3 次，全题组使用通过专家回放的 24 道 Train 候选各 1 次。两组分别从相同 SFT v2 开始，均有 24 个训练组、每组 4 条在线采样。全题组按固定随机种子 42 排序，训练不读取 Probe 选题信号或 Dev 成绩。19/24 个全题组来自至少四次工具调用的任务，筛选组为 12/24。两个计划共享同一训练实现、四步 Smoke 验证、无效组掩码与奖励设置。此对照同时改变题目覆盖、重复次数及家族分布。

全题组使用独立输出根目录，调用 `dfa_transfer.py --all-candidates`。共用已核验的 SFT Dev、封存集和历史生产集基线。两个 Adapter 分别在 Dev 冻结后接受同题同种子的封存集及生产 Benchmark，分别保留原始配对和训练 Token 记录。全题组在看到筛选组 Smoke 后增加，属于探索性对照。两个结论均应结合逐题差异和环境缺项解读。

比较时同时报告两个模型相对 SFT 的逐题修复与回退，以及全题组直接相对筛选组的配对变化。Challenge 主表保留所有原始试次，另列两模型共同可判定的试次、按题聚类的区间和三个模型都可判定的结果。原生产集报告 Dev、IID、OOD 与总计。训练端列出真实 Strict 对照组、实际获得非零 DFA 优势的组和 Token，额外检查全题组的信号是否来自筛选时排除的题。每种训练策略各运行一个训练 Seed，评测的三次重复无法估计训练 Seed 间方差。
