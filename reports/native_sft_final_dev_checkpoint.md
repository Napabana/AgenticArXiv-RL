## 生成文本的复核口径

- 工具前 Content 核对事实是否来自用户、会话或此前 Observation，是否把计划当成已经执行的结果，以及陈述的动作是否与同轮调用一致。
- Final Answer 核对正确论文与实际状态，是否交付所有必需结果，拒绝时是否如实说明能力边界。一项任务的多个试次分别记录。
- Tool Sequence Accuracy 与 effective Argument Accuracy 采用已有 Benchmark 评分。人工发现的问题同时保留在本报告和原始逐轮轨迹中。

## 第二个 Epoch 判断

当前保留第 64 步作为最终检查点。第 50–64 步 Dev Loss 仅再下降约 0.0027，工具序列和参数有所改善，Dev 严格成功率仍为 70.8%。Dev 的 7 次失败集中在能力边界、检索范围及完成全部子目标。

全协议评测严格成功由 46/93 升到 69/93。IID 从 20/57 升至 45/57，OOD 从 9/12 降至 7/12。OOD 里，`multi_cv5_dl1_cache_tr` 的 3 个回退都发生在下载之后，模型跳过缓存查询直接提交翻译。另一个回退 `multi_cl5_dl2_cache` 的工具序列和参数均正确，最终回答重复并达到长度上限。OOD 中的 2 个改善来自 AI 检索、下载和提交翻译链。

第二个 Epoch 可单独作为受控实验。若后续启动，从完整 `checkpoint-64` 恢复 LoRA、优化器及随机状态，以 `1e-5` 或 `2e-5` 为候选初始学习率，开启短 warmup 和新的 cosine 调度，用 Dev 检查一个额外 Epoch 的增益。本轮具体训练和评测均以第 64 步为终点。
