# Native SFT 约束遵守与多步完成补齐方案

## 设计依据

Dev 上 Base 和 SFT 都是 15/24，但有 6 次改善和 6 次回退。值得单独补齐的训练覆盖已经可以具体定位。

| 回退行为 | 当前监督覆盖 | 下一轮目标 |
| --- | --- | --- |
| 用户要所有 CS、明确不要保存，SFT 三次都选了 CL 且 `save_to_file=true` | 83 条分类检索调用全部保存，全 CS 短码 `*` 只出现 1 次 | 将检索范围和保存限制作为两个独立条件，用户明确禁止保存时覆盖默认值 |
| 用户要下载后查缓存，两次下载后提前回答，另一次做完调用但最终回答触顶 | 95 个承接下载的监督决策中，35 个直接回答，0 个直接查缓存 | 按实际请求区分只下载、下载后查缓存、只查缓存三种行为 |
| 不支持发送约稿邮件的 Dev 试次，两组都未做到合格拒绝 | 已有缺上下文、越界与未知 ID 的拒绝样本，另有一条能力边界 SFT-only 样本 | 让模型根据用户明确要求的动作和真实工具能力决定零调用、询问或执行获准步骤 |

前两行是日志与覆盖统计的对应关系。按下文独立对照验证提示或数据能否改善这些错误。当前评测继续使用冻结版本。

## 提示词和工具定义

System Prompt 增加以下通用规则。

> 把用户明确表达的禁止条件、范围限制和步骤顺序视为任务要求。工具默认行为与用户限制冲突时，按工具定义选用能遵守限制的参数。
> 根据用户请求和真实 Observation 确认还有哪些要求待完成。执行一个步骤后，只有全部必需步骤完成，或有明确阻塞时，才给最终回答。
> 当核心目标缺少必要上下文、引用无效或工具能力无法满足时，说明具体阻塞。任何可选或无关操作都需要有用户目标作为依据。用户明确要求的独立子目标仍可执行时，按原限制完成并分别汇报结果。

Tool Schema 保留逐参数契约。分类检索的 `save_to_file` 简明说明 `true` 写出列表、`false` 仅返回检索结果、默认 `true`。明确禁止写文件时使用 `false`。当其为 `false` 时，`output_path` 仅是无效参数，样本统一写成 `null`。缓存工具说明它读取下载及翻译状态，单独查询缓存不会启动下载或翻译。

## Train 对照族

每组对照保持同一快照、候选论文和检索参数，只改变需要模型识别的请求条件。首批采用 3 对保存约束、3 组三分支下载与缓存、3 对能力情形作为起点，约 21 条候选轨迹。按覆盖情况增减，同一轨迹的单纯换措辞不计覆盖增量。

| 对照族 | 候选输入 | 必需的专家行为 | 来源 |
| --- | --- | --- | --- |
| 保存开关 | 全 CS，近 3 天，最多 4 篇。一条明确不要写文件，另一条明确保存检索结果 | 两条都调用分类检索、`aspect="*"`。前者 `save_to_file=false`，后者 `true` | Train `constraint_search_only` 的新参数实例 |
| 保存开关与子领域 | CV 近 14 天最多 4 篇、CL 近 5 天最多 3 篇。各一条不保存和一条保存 | 正确区分 `aspect`、`days`、`max_results` 与保存开关 | Train `search_CV_14d_3`、`search_CL_7d_5` 的参数变体 |
| 下载决策 | 先设 CL 近 14 天、5 篇候选。对第 2 篇分别请求「只下载」「下载后查缓存」「只看下载和翻译缓存」 | 三种应答分别走 `download`、`download → cache`、`cache`。工具全部用同一指代 | Train `constraint_download_only`、`constraint_cache_only` 和 `state_cache_before_dl` |
| 下载决策泛化 | 再用 CV 近 10 天、4 篇候选的第 3 篇，以及 LG 近 3 天、5 篇候选的第 4 篇做相同三分支 | 每一分支严格检查工具序列与终止时机。缓存结果如实反映当前 READY 状态 | 同一训练族的新 setup 与引用 |
| 只执行获准子目标 | 同一已有论文对象。对照「查一下缓存」与「只把原 PDF 移到另一个目录」 | 前者一次缓存调用。后者现有工具不支持移动文件，说明原因并零调用 | Train `constraint_cache_only` 和新 SFT-only 能力边界 |
| 相同指代、不同状态 | 相同请求「读出先前处理过的那篇论文摘要」。一条是空 Session，另一条 setup 明确处理过 AI 候选第 2 篇 | 空 Session 说明缺少论文对象。有上下文直接调用 `get_paper_content(ref=null)` 并引用摘要证据 | Train `infeasible_no_session` 与 `read_ai5_default` |
| 能力范围的区分 | 在相同已下载状态，一条请求列出 PDF 图表，另一条只请求给 PDF 加水印 | 前者在有快照记录的同一论文上抽图。后者说明无 PDF 编辑工具并零调用 | Train `figure_cv5_ref1` 与新 SFT-only 能力边界 |

三个下载 setup 的候选序号在当前 Snapshot 的对应列表中均存在：CL 第 2 篇 `2611.18527v1`、CV 第 3 篇 `2608.14539v1`、LG 第 4 篇 `2611.18559v1`。AI 第 2 篇为 `2608.14530v1`。这些是候选定义，纳入训练前须在当前 Native Agent 上逐步回放并检查实际返回的 ID、状态和内容。图表对照可选择当前 CV 第 1 篇 `2608.14546v1`，仍须校验其图表记录。

Dev 的「全 CS、7 天、5 篇、不保存」以及「AI、7 天、5 篇 setup 后下载第 1 篇再查缓存」留在评测。入 Catalog 之前，以 v4_86 做来源 ID、任务文本和归一后的 setup/steps 参数组合检测，也覆盖 IID 与 OOD。

## Content、终止和验收

- 下载回执为 READY 且用户要求缓存确认时，下一轮 Content 说明下载已完成，并直接发起缓存查询。只要求下载时，直接汇报下载结果。只要求缓存时，即使 PDF 未下载，也如实回答缓存状态。
- 分类检索结果只陈述 Mock 实际返回的论文。离线 Replay 不写真实检索文件，保存开关从调用参数审计。另用 stub arXiv Client 和临时目录测试真实工具，验证 `false` 不产生文件、`true` 使用工具约定路径。
- 支持性对照必须真实跑完工具和最终回答。不支持、无对象或非法引用属于明确定义的零调用完成状态。出现意外 Snapshot miss 时，调整候选定义并重新回放。
- 每条对照保持完整 Native 交互。当前 Assistant Content 和 Tool Call 或 Final Answer 计入 Loss；System、User、历史与 Observation 均经过真实 Qwen 模板和 TRL mask 审计。
- 每族保留至少一组未参与训练的新诊断对照。先用相同模型和种子比较现提示与补充后的提示，测用户限制是否得到遵守。后续再评估补充数据的独立增量。提示或数据有变化时，用同一条件重跑成对 Base/SFT，保留本轮结果。
- 本轮全部 93 对评测完成后，按实际错误变化决定其他补齐项。优先看两组集中发生的回退、长期未改善的错误和多个任务共享的失败机制。



## 全量错误后的补齐设计

全量完成后，SFT 的 29 个失败试次可按首个不达标层级分为 11 个工具序列错误、12 个参数或引用错误、6 个终止错误。每条都从同一 v4_86 任务的 Base 和 SFT 配对轨迹核对。以下扩展继续采用独立 Train 对照。

| 优先项 | 全量证据 | SFT 设计修改 | 验收信号 |
| --- | --- | --- | --- |
| 工具已做完后的收尾 | 6 个失败的工具序列和参数均正确。查缓存 1 次、提交翻译 3 次、生成摘要 2 次在最终回答重复论文 ID 或 PDF READY 句子，触到单轮生成上限 | 增补短而完整的最终回答目标。下载后查缓存只归纳下载与缓存状态。翻译最后提交时交代任务已受理和 PENDING。摘要完成时交付摘要正文。每个子结果汇报一次。若历史工具回执过长，先压缩其展示字段并保留支撑事实，再重新验证最终回答与结束符的监督 | 工具成功后生成正常的最终回答，Qwen 轮结束符在监督标签内。比较最后一轮的截断和重复次数 |
| 活跃引用和双语选项的组合 | 翻译限定题三次都把双语设为 false。25 条训练翻译调用中有 7 条 keep_dual=true，0 条同时有 ref=null 和 keep_dual=true | 对另一组已下载论文做成对任务。两条都指代「刚下载的那篇」，一条保留双语，另一条仅输出中文。规范调用分别为 ref=null、keep_dual=true 与 ref=null、keep_dual=false。附带 no-search、no-cache 的任务限制 | 单次 translate 完成受理，引用解析为实际活跃论文，双语值匹配请求，零额外调用 |
| 显式摘要与默认章节 | 3 次实际读到了目标论文的标题和摘要，调用为 section=null；当前专家参数是 section=abstract。固定 Snapshot 中两者均含摘要，默认版本还返回标题 | 在另一篇同时有默认正文和 abstract 键的论文上补「标题及摘要」和「只读摘要章节」对照。明确要求只读摘要时监督 section=abstract。若评测措辞只要求摘要，另外审阅标题加摘要是否能按语义等价计分 | 训练工具目标与措辞边界一致。对语义等价的评分判断有单独回归证据。本轮已冻结分数保留 |
| 多对象与标题定位 | 分别查两篇缓存的 3 次均漏掉第二篇。要求标题包含 Learning State 的 3 次均下载了第 1 篇，实际匹配是第 3 篇 | 添加两篇或三篇缓存查询，明示第二个对象必须完成。用其他 Train 论文的唯一标题片段构造不同列表排名，覆盖第一项是干扰项时的直接标题引用 | 逐项核对完整序列和 paper_id。最终回答列出每个请求对象自己的结果 |
| 越界与能力边界 | SFT 的 6 次拒绝试次都出现了无关调用或越界下载。越界题明知列表只有 5 篇仍尝试 ref=20 | 在 CV 或 CL 列表上构造同一 setup 的合法末位与越界相邻引用对照，配合前文只查缓存与不支持文件编辑的 SFT-only 对照 | 合法引用实际执行，越界或单一不支持目标零工具调用并解释具体原因 |

新增候选继续绑定同一 Snapshot SHA256。先核验实际论文、所需章节和工具状态，再进入专家 Catalog。当前任务已经改善的重复调用（16 个试次降至 1 个）和多余 PENDING 后续动作（4 个触发拦截的试次降至 0 个）作为回归观察项。上述修改处于设计阶段。
